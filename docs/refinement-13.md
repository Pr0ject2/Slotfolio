# Refinement 13 — каталог 1000+, сравнение пар и медиаполитика

Итерация v123 не меняет визуальную концепцию Astra. Основная цель — убрать технические ограничения, которые стали бы заметны при росте каталога до 1000+ игр.

## Каталог

- Полные досье остаются в `src/lib/data.ts`, но клиент каталога больше не импортирует этот массив.
- `src/lib/catalog-index.ts` формирует на сервере компактные записи только с полями, которые нужны списку, поиску и фильтрам.
- Счётчики провайдеров, механик, волатильности и особенностей считаются один раз при формировании модели, а не через повторные `slots.filter(...)` при каждом рендере.
- `src/lib/catalog-query.ts` отделяет чистую логику поиска/фильтрации/сортировки от React и полного слоя данных.
- Результаты фильтрации мемоизированы; строка поиска использует `useDeferredValue`, поэтому ввод не блокируется пересчётами большой выборки.
- Карточки по-прежнему рендерятся порциями по 18, поэтому 1000 результатов не создают 1000 DOM-карточек сразу.

На синтетической выборке 5000 компактных записей комбинированный фильтр выполнился примерно за 63 мс в текущем Node-окружении. Это не браузерный benchmark, а sanity-check архитектуры: линейный поиск по 1000–3000 компактных записей остаётся разумным без backend.

## Сравнение

- Максимум уменьшен с трёх игр до двух.
- `CompareButton` больше не импортирует `data.ts`; кнопка хранит только slug выбранных игр.
- Само сравнение вынесено из `catalog.tsx` в отдельный компонент.
- Все готовые пресеты стали парами.
- Таблица и блок выбранных игр адаптированы под две колонки.
- Комбинаторный тест всех троек удалён. Вместо него проверяется ограниченная репрезентативная выборка пар и отдельно масштабная работа каталога.

## Изображения

- Удалены семь старых дублей из `public/images`, включая PNG 1200×630 весом около 1,27 МБ.
- Стандартная SEO-картинка теперь использует уже существующий WebP.
- 31 актуальный WebP после повторной оптимизации занимает около 1,16 МиБ, средний файл — около 38 КБ.
- Обычная игровая графика ограничена 960×540, крупная feature/OG-графика — 1200×630.
- Новые изображения кодируются адаптивно в WebP: качество 76, затем 72/68, если файл остаётся тяжёлым.
- Manifest `local` теперь определяет фактический путь вывода, поэтому позже можно без переписывания скрипта разнести тысячи файлов по подпапкам провайдеров или другим shard-папкам.
- Production build больше не скачивает картинки из интернета. `prebuild` только проверяет локальные файлы. Сетевой импорт запускается отдельно через `npm run assets:localize`.

При текущем среднем весе 1000 игровых изображений дают ориентир около 38–40 МиБ. Даже с запасом это значительно ниже ограничений статического репозитория, поэтому отдельный CDN ради одного только числа слотов пока не нужен.

## Проверка

- Полный `tsc --noEmit` проходит доступным в окружении TypeScript 5.8.3 с типами проекта.
- `scripts/localize-slot-images.mjs` проходит `node --check`.
- Все 31 записи image manifest имеют локальный файл; превышений новой политики размеров/веса нет.
- Скомпилированные отдельно data/query/index модули формируют модель 30 игр, 7 провайдеров и 5 механик; синтетическая выборка из 5000 записей корректно фильтруется и сортируется.
- Полный `npm run build` в этом Linux-окружении не заявляется: доступный `node_modules` был создан в Windows и не содержит Linux optional packages TypeScript/Sharp/Next SWC, а npm registry недоступен.
