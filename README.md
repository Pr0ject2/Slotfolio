# Slotfolio

Slotfolio — редакционный каталог слотов на Next.js 16 App Router, React 19 и TypeScript. Проект собирается статически для GitHub Pages, но структура данных и клиентский каталог рассчитаны на дальнейшее масштабирование без немедленного перехода на отдельную БД.

## Текущее состояние

- 1000 уникальных записей в игровом указателе.
- 100 полноценных редакционных досье с проверенными характеристиками и отдельными маршрутами `/slots/[slug]`.
- 900 дополнительных каталожных записей, подтверждённых официальными каталогами провайдеров, без выдуманных RTP, волатильности, года, механик или artwork.
- Поиск, комбинированные фильтры, сортировка и порционная выдача по 18 карточек работают по всему указателю из 1000 игр.
- Сравнение максимум двух игр доступно только для полноценных досье и сохраняет выбор в `localStorage`.
- Профили провайдеров, страницы механик, редакционные статьи, подборки и GEO-раздел.
- Канонические URL, Open Graph / Twitter metadata, sitemap.xml, robots.txt и JSON-LD.
- Локальные runtime-изображения; внешние CDN используются только как проверяемые build-time источники.
- Индексация по умолчанию выключена до отдельного решения о публикации.

## Два уровня покрытия

Каталог намеренно разделён на два уровня, чтобы масштабирование не превращалось в генерацию недостоверных карточек.

**Полное досье** содержит редакционно проверенные характеристики игры: RTP и его контекст, волатильность, механики, особенности, изображения, источники и материалы для сравнения.

**Каталожная запись** подтверждает только то, что уже можно обосновать официальным источником провайдера: название игры, провайдера и ссылку на источник. Пока характеристика не проверена отдельно, Slotfolio не подставляет приблизительный RTP, случайную волатильность, предполагаемый год или изображение другой игры.

Каталожные страницы `/slots/catalog/[slug]` остаются `noindex` и не попадают в sitemap, пока не превращены в полноценные редакционные досье.

## Запуск

Требуется Node.js 20.9+; GitHub Actions использует Node 22.

```sh
npm ci
npm run dev
```

На Windows PowerShell при запрете `npm.ps1` можно использовать `npm.cmd`.

Локально сайт доступен на `http://localhost:3000`.

## Production-проверки

```sh
npm run typecheck
npm run assets:localize
npm run assets:verify
npm run build
npm test
```

Обычный `npm run build` намеренно строгий: `prebuild` проверяет, что обязательные локальные игровые изображения для полноценных досье уже подготовлены. Временное отсутствие подтверждённого artwork не маскируется случайным OG-баннером, логотипом провайдера или изображением другой игры.

GitHub Pages использует отдельный preview-путь: workflow запускает локализацию в `--soft` режиме и затем прямой `next build`. Поэтому временно неподтверждённая обложка не ломает preview — компонент `SlotArtwork` использует локальный `/images/unavailable.svg` — но строгая локальная проверка продолжает показывать незакрытый artwork-долг.

Pull request CI отдельно прогоняет TypeScript, production static build и полный Playwright до слияния изменений в `main`.

## Архитектура данных

`src/lib/data.ts` — каноническая публичная точка входа для 100 полноценных досье. Она реэкспортирует объединённую модель из `data-v128.ts`.

`src/data/catalog-seeds.json` содержит более широкий пул записей из официальных каталогов провайдеров. `src/lib/catalog-seeds.ts` проверяет доверенные домены источников, удаляет дубли и пересечения с полными досье и выбирает ровно столько записей, чтобы итоговый публичный указатель составлял 1000 игр.

Данные разбиты на слои:

- `src/lib/data-base.ts` — исходный базовый каталог и общие типы/утилиты;
- `src/lib/slot-additions-*.ts` — последовательные партии полноценных досье;
- `src/data/catalog-seeds.json` — проверенный пул каталожных записей;
- `src/lib/catalog-seeds.ts` — валидация источников, дедупликация и ограничение итогового размера;
- `src/lib/provider-profile-overrides.ts` и `provider-profile-additions-*.ts` — редакционные профили провайдеров;
- `src/lib/dossier.ts` — дополнительные проверенные метрики и feature cards;
- `src/lib/catalog-index.ts` — объединённая компактная модель из досье и каталожных записей;
- `src/lib/catalog-query.ts` — клиент-безопасная логика поиска, фильтров и сортировки.

Один `slug` не может породить две публичные карточки. Тесты отдельно требуют 100 полноценных досье, 900 каталожных записей, 1000 итоговых элементов и 1000 уникальных slug.

## Источники каталожных записей

Расширенный пул собирается только с официальных сайтов провайдеров. Текущий конвейер умеет проверять записи из каталогов Play’n GO, Hacksaw Gaming, Push Gaming, BGaming, Endorphina, Nolimit City, Wazdan и 3 Oaks Gaming. В коде действует allowlist доверенных доменов, поэтому случайная ссылка на сторонний агрегатор не становится подтверждённым источником.

Исследовательские скрипты находятся в `scripts/harvest-*.mjs`. Они отделены от runtime сайта и используются для построения проверяемого seed-пула. После сбора `scripts/build-catalog-seeds.mjs` удаляет очевидные неслотовые игры, дубли и мусорные элементы навигации.

## Основные маршруты

| Назначение | Адрес |
| --- | --- |
| Главная | `/` |
| Каталог | `/slots` |
| Поиск | `/search` |
| Полное досье | `/slots/gates-of-olympus` и ещё 99 исследованных игр |
| Каталожная запись | `/slots/catalog/[slug]` |
| Сравнение | `/compare` |
| Механики | `/mechanics`, `/mechanics/cascades` |
| Провайдеры | `/providers`, `/providers/pragmatic-play` |

| Разборы и гайды | `/journal` |

Sitemap строится из полноценных досье, механик, редакционных профилей провайдеров и системных страниц. `/search`, `/compare` и промежуточные `/slots/catalog/*` не индексируются как самостоятельные SEO-страницы.

## Изображения игр

Все изображения, используемые браузером для полноценных досье, должны быть локальными.

Manifest-ы происхождения находятся в:

- `docs/image-sources.json`;
- `docs/image-sources-v128.json`;
- `docs/image-sources-v129.json`;
- `docs/image-sources-v130.json`.

`requireExplicitImage: true` означает, что для игры требуется отдельно проверенный game-specific URL. Общий `og:image` страницы не принимается автоматически как игровая обложка.

Ограничения медиаполитики:

- обычная обложка: максимум 960×540, целевой вес до 140 KB, жёсткий предел 220 KB;
- feature / OG: максимум 1200×630, целевой вес до 180 KB, жёсткий предел 260 KB.

Локализатор кодирует WebP через `sharp`, кэширует build-time источник в `.asset-cache/slot-images` и не создаёт runtime-зависимости от внешнего CDN.

Каталожная запись без проверенного artwork использует нейтральный локальный placeholder и не заимствует изображение у другой игры.

## 1win и проверка доступности

Для полноценных досье, добавленных после введения операторской политики, поле `availability` хранит источник и дату подтверждения присутствия в 1win. Это подтверждает наличие игры в публичных материалах оператора, но не подменяет живую проверку конкретной операторской сборки, RTP или спорных метаданных.

Расширение указателя до 1000 не означает автоматического утверждения доступности всех 1000 игр у конкретного оператора. Для новых каталожных записей операторская доступность остаётся неизвестной, пока не подтверждена отдельно.

## Партнёрская интеграция

Настройки находятся в `src/lib/affiliate.ts`; серверный переход — `/go/[operator]`. `AFFILIATE_1WIN_URL` можно задать только после проверки адреса и условий. Без подтверждённого URL интерфейс использует безопасный информационный fallback.

GitHub Pages — статический preview, поэтому server-side redirect удаляется только из временной сборочной копии в workflow и остаётся в исходном проекте.

## SEO и публикация

Канонический адрес задаётся через `NEXT_PUBLIC_SITE_URL`.

`NEXT_PUBLIC_INDEXABLE=false` запрещает индексирование. После готовности к публикации индексацию можно включить repository variable `NEXT_PUBLIC_INDEXABLE=true`; `/search`, `/compare` и промежуточные каталожные записи всё равно останутся `noindex`.

## QA

Playwright и unit-проверки контролируют:

- итоговые 1000 уникальных элементов каталога;
- разделение 100 полных досье и 900 каталожных записей;
- отсутствие выдуманных RTP, волатильности, механик и года у catalog-only записей;
- публичные маршруты, внутренние ссылки и заголовки;
- локальные изображения и fallback;
- поиск, фильтры, сортировку и пагинацию по расширенному каталогу;
- сравнение и ограничение в две исследованные игры;
- профили провайдеров и механик;
- SEO metadata, JSON-LD, sitemap и robots;
- мобильное меню и FAQ;
- переполнение на 320, 360, 390, 430, 768, 1024 и 1440 px.

Исследовательские файлы, скриншоты и build-time cache не являются частью runtime сайта.

## Документы

В `docs/` находятся design research, visual system, QA/refinement notes и журналы происхождения изображений. Для актуального состояния каталога источником истины являются код, тесты, `catalog-seeds.json` и текущие manifest-ы; исторические refinement-документы сохраняются как журнал развития проекта.
